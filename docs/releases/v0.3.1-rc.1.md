# dsh-approval-center v0.3.1-rc.1（预发布）

这是适配 DeepSeek Harness（DSH）`0.1.7-rc.2` 的 Windows 审批中控台预发布版。插件通过 Windows 通知中心展示批准／拒绝按钮，并记录审批结果，适合先在隔离 profile 中验证，再按备份流程升级。

## 适用环境与安装

- **宿主版本：仅声明兼容 `@deepseek-ai/dsh` `0.1.7-rc.2`。** 请先运行 `dsh --version` 核对；`0.1.5-rc.1` 的测试仅用于观察，不构成兼容承诺。
- Windows、Node.js 24 或更新版本；使用 `dsh plugin` 安装时，PATH 中需有可运行的 `pnpm`。安装前可检查 `node --version` 与 `pnpm --version`。
- 从本 Release 下载固定资产：[dsh-approval-center-0.3.1-rc.1.tgz](https://github.com/xmwpoi/dsh-approval-center/releases/download/v0.3.1-rc.1/dsh-approval-center-0.3.1-rc.1.tgz)。此预发布包通过 GitHub Releases 分发，未发布到 npm 注册表。

```powershell
dsh plugin --profile web add https://github.com/xmwpoi/dsh-approval-center/releases/download/v0.3.1-rc.1/dsh-approval-center-0.3.1-rc.1.tgz
```

如果使用其他 profile，请将命令中的 `web` 换成实际 profile。安装后确认只启用一个审批中控台实例，并执行一条受控的批准和拒绝请求，核对通知回传与审计记录。

安装包已包含 `lib/`，无需克隆仓库或手动编译；不要用 GitHub 自动生成的 **Source code** 压缩包替代 `.tgz`。可同时下载 [SHA256SUMS.txt](https://github.com/xmwpoi/dsh-approval-center/releases/download/v0.3.1-rc.1/SHA256SUMS.txt)，与本地 SHA256 对照后从本地安装：

```powershell
Get-FileHash -LiteralPath 'C:\Downloads\dsh-approval-center-0.3.1-rc.1.tgz' -Algorithm SHA256
dsh plugin --profile web add 'C:\Downloads\dsh-approval-center-0.3.1-rc.1.tgz'
dsh --profile web --dump-config
```

默认只开启待审批通知；任务启动/结束和审批结果回执为可选配置。请保持 `timeoutAction: reject`，除非你明确希望无人应答超时后自动批准。未开启 HMR 的宿主需要结束旧进程后重启。

## 本次改进

- 对齐 DSH `0.1.7-rc.2` 的审批契约，包括 `displayReason` 展示、结果映射、排队取消及插件卸载结算。
- 对通知和 URI 回传做请求级定向清理；中文及含空格的私有状态目录使用跨代码页的 Unicode 映射，避免回传落入错误目录。
- 审计存储增加单实例锁、崩溃恢复和幂等结算；批准结果无法完成审计结算时按渠道不可用处理，不显示已放行的回执。
- 分离自动单测、真实宿主非交互集成测试和 Windows 人工验收，便于复查各层证据。

## 验证范围与已知边界

自动单测 **98/98**、DSH `0.1.7-rc.2` 真实宿主非交互集成 **21/21** 通过。Windows 实机对新包受影响路径复测 **C5/5** 通过；该结果覆盖限定的通知／URI 回传与清理路径，不能外推为所有使用场景均已验证。

最终发布包仅更新介绍与安装文档；除 README/CHANGELOG 外的 17 个运行及配置文件须与实机验收包逐字节一致，实际发布 SHA 见附件校验清单。

完整真实子代理会话通知（V16）、更大批次的真实并发、以及生产环境升级后再回装旧版，均尚未完成实测。`0.1.5-rc.1` 只有独立的观察性回归记录，本版本不承诺支持该宿主版本。生产环境请先用隔离 profile 验证，并保留可执行的回滚路径。

## 升级、备份与回滚

从 `0.3.0` 升级前，先停止旧插件实例，记录当前插件来源与宿主版本，备份 profile 的包、锁文件和补丁配置。审计库使用 SQLite WAL：**首选停机后同时备份 `approvals.db`、`approvals.db-wal`、`approvals.db-shm`**；若必须在运行中备份，应使用 SQLite backup 机制，不能只复制主数据库文件。升级后再核对配置中仅有一个实例，并检查批准／拒绝各一条审计终态。

需要回滚时，先停止候选实例并再次完整备份审计库，再恢复旧 profile 包、锁文件和补丁配置，核对 URI 注册仍指向有效安装位置。旧版打开数据库可能把残留的待决记录改写成 `timeout`，因此回滚前的备份不可省略。完整步骤见[升级、WAL 备份与回滚清单](https://github.com/xmwpoi/dsh-approval-center/blob/v0.3.1-rc.1/docs/compat/drafts/store-and-rollback.md)。生产升级后回装旧版尚未演练。

遇到审批卡住、通知按钮无法回传、审计异常或安装问题，请附上 DSH／Node 版本、插件安装方式及脱敏日志，在 [GitHub Issues](https://github.com/xmwpoi/dsh-approval-center/issues) 反馈。
